# pi-data-masking 问题场景清单(Pitfalls)

> 来源:0.3.0 设计讨论 + 真机实测(2025-08)。按"机制 → 缓解 → 状态"组织。
> 相关文档:docs/design-proposal.md(方案)、README.md(使用)。

## 一、基于脱敏显示信息做语义判断(观察者陷阱)

- **机制**:占位符与真实值同格式、同长度、同字符集,观察者(LLM 或人)无法仅凭外观区分。任何基于"看到的内容"做出的判断——写断言、复制值、比较、分类——都可能建在假值上。
- **亲历实例**(0.2.1 会话):LLM 读配置文件看到占位符形式,误当真实值写入测试断言(`startsWith("gs-")` 失败);随后把 od 输出的真实值反复误读成占位符。
- **缓解**:
  1. 测试/文档数据一律用**不匹配任何规则**的值;
  2. 关键内容用 `od -c` 等逐字节核验(od 输出字符间有空格,占位符替换无法命中,是可信的地面真相);
  3. 不把显示值当真实值引用、回写;
  4. `preserveStructure.keepPrefix` 让"前缀类"判断对真实/占位符一致。
- **状态**:不可根除(LLM 永远只见占位符是设计使然),只能靠纪律。

## 二、LLM 对占位符做变换

- **机制**:算术、拼接、截取、哈希基于假值,结果不可逆还原(例:`把 12338221422 加一得到 123382214221`),会话中留下假值。
- **缓解**:`options.systemPromptGuidance`(默认关)告知 LLM 占位符是不透明 token、禁止变换;占位符 **verbatim** 传给工具时由 `tool_call` 边界还原,这条路径是安全的。
- **状态**:不可根除。

## 三、语义属性断言断裂

- **机制**:格式保持保形状不保语义——`"123456 是弱密码"` 脱敏后变成 `"834919 是弱密码"` 假命题;LLM 为消解矛盾甚至可反推真实值(推断泄露)。
- **缓解**:低熵值不脱敏(0.3.0 配置加载警告 + 规则设计原则:只脱敏高熵、语义透明的值)。
- **状态**:已缓解,取决于规则设计。

## 四、结构属性断言断裂

- **机制**:`"这个 key 以 sk- 开头"` 这类断言文本不含完整值、不命中规则而幸存,值与断言不一致。
- **缓解**:`preserveStructure.keepPrefix`(保留首段)、`keepIPv4Octets`(保留私网前段);连接串/域名本就保留 scheme/port/TLD。
- **状态**:部分解决——指向主体片段的断言(如"mxr 那段")无解:保留=泄露熵,不保留=断言断裂,只能按敏感度二选一。

## 五、巧合还原

- **机制**:LLM 输出恰好等于某已知占位符 → `message_end` 无条件还原 → 真实值出现在 LLM 本意无关的文本中。概率与占位符熵成反比(6 位数字占位符远高于 40 字符 token)。
- **缓解**:0.3.0 起 LLM 自造值不注册(unmask 扫描面缩小);低熵值不脱敏。
- **状态**:概率显著降低,无法归零(占位符方案的固有残余)。

## 六、首见定终身泄露(接受的取舍)

- **机制**:LLM 先自造某值 → 用户之后发送同值 → 明文直发 provider(首见定终身,含字面量规则)。
- **缓解**:高熵值巧合概率≈0;低熵值已建议不脱敏。
- **状态**:接受;实际风险趋近于零。

## 七、配置与规则设计陷阱

- 规则 `real` 是模板示例值 → 规则实际不保护任何真实数据(检查你的配置是否替换了示例值);
- 低熵规则(4 位码、`password=` 短值)→ 第三、五类风险集中;
- **键名驱动(key-name-driven)规则整类不可用**:按"敏感键名 = 值"匹配的正则,无论怎么收紧都既误伤又漏——旧示例 `keyword_value_pairs`(裸 `key`/`token`、大小写不敏感)会脱敏 `const KEY = Buffer.from(...)`、`// Key: 32 hex chars`、`reg_key = HKDF-SHA256(`、`key: "server.rsa.key"`;收紧后的 `env_secret_values`(仅大写 env 风格)仍会脱敏 `API_KEY = os.environ[...]`、`SECRET: HKDF-SHA256(...)`、`PASSWORD: change-me`,同时漏掉 `DJANGO_SECRET_KEY=...`(键名后缀式)。正例:按**值的结构特征**脱敏(`ghp_`、`AKIA`、`eyJ`、PEM 块、Bearer 前缀),已知值用字面量规则;
- 人肉从脱敏显示中复制值写文件会写入占位符(工具调用写入会被 `tool_call` 还原,人不会)。

## 八、会话生命周期

- 重启后旧会话历史被重扫并重新脱敏:一次性的计数(工具消息按真实数据源处理,符合设计);
- 会话文件(`~/.pi/sessions/`)存真实值——注意文件权限(README Limitations);
- 用户秘密经 LLM 回显还原后,下一轮历史中必须再 mask 防回流(0.3.0 已实现并实测)。
